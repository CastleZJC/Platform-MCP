# 1. 文档概述

## 1.1 项目背景
Platform_MCP 项目拟建设一套面向内部使用的 MCP 能力平台，首期聚焦数据库相关能力，通过标准化 MCP 接口向 Claude Code 等调用方提供 SQL 执行、校验、数据源访问等能力，并通过 Web 管理端实现统一的配置管理、权限控制、审计追踪和运行状态查看。

本项目并非传统的“Web 在线 SQL 编辑平台”，核心执行入口为 MCP，Web 端主要承担管理、审计和运维支撑职责。

---

## 1.2 建设目标
本项目的建设目标包括：

- 建设统一的 MCP 服务入口，支撑 Claude Code 调用
- 首期落地数据库 Skill 能力
- 支持通过 MCP 执行本地 `.sql` 文件内容或 SQL 文本
- 提供统一的用户、权限、环境和数据源管理能力
- 提供完整的执行审计、风险记录和调用状态查看能力
- 支持 Oracle 11g、MySQL 5.6 等存量数据库的兼容接入
- 保留后续扩展其他 Skill 的能力，避免首期架构固化

---

## 1.3 文档范围
本文档主要说明以下内容：

# 2. 项目定位

## 2.1 系统定位
Platform_MCP 的定位为：

- 一个面向内部使用的 **MCP 能力服务平台**
- 一个以 **数据库 Skill** 为首期核心能力的 MCP 服务
- 一个具备 **权限、审计、配置管理、状态监控** 能力的管理平台
- 一个可持续扩展其他 Skill 的统一能力底座

---

## 2.2 与传统 SQL 平台的区别
本项目与传统在线 SQL 管理平台的差异如下：

1. **SQL 不在 Web 端编辑**
   - Web 端不提供主要 SQL 编写入口
   - SQL 主要由 Claude Code 通过 MCP 调用执行

2. **执行入口是 MCP**
   - Claude Code 通过 MCP Tool 调用本系统
   - 系统负责执行、记录、审计和返回结果

3. **Web 端以管理为主**
   - 用户管理
   - 数据源管理
   - 密码加解密
   - MCP 调用状态查看
   - 审计日志查看
   - 配置管理

---

# 3. 建设原则

## 3.1 架构原则
- 采用 **单体应用 + 模块化设计**
- 首期聚焦数据库 Skill，不引入过度复杂的分布式架构
- 保持核心能力内聚，便于实施、部署与维护
- 通过清晰模块边界为后续扩展保留空间

---

## 3.2 技术原则
- 以后端稳定性、兼容性、可维护性为优先
- 优先兼容 Oracle 11g、MySQL 5.6 等老版本数据库
- 管理端与执行端逻辑统一纳入同一后端体系
- 避免过早引入高复杂度基础设施

---

## 3.3 扩展原则
- MCP 层采用 **Skill 插件式扩展思想**
- 首期仅交付 `database skill`
- 后续可平滑扩展 `file`、`log`、`config` 等其他 Skill
- 扩展其他 Skill 时，不推翻现有 MCP 主框架

---

# 4. 总体架构设计

## 4.1 总体架构说明
系统采用以下总体结构：

- **Web 管理端**
- **Java 后端服务**
- **MCP Server 能力层**
- **Skill 实现层**
- **PostgreSQL 系统库**
- **目标数据库连接层**

整体调用关系如下：

**Claude Code**  
→ 调用 **MCP Server**  
→ 路由至 **database skill**  
→ 调用 **SQL 执行模块**  
→ 连接目标数据库执行  
→ 返回结果并写入审计日志  

同时：

**Web 管理端**  
→ 调用 **Java 后端管理接口**  
→ 管理用户、权限、数据源、密码、审计、MCP 状态等信息

---

## 4.2 架构分层

### 4.2.1 表现层
包括：
- Web 管理页面
- 管理 API 接口
- MCP Tool 接口入口

---

### 4.2.2 能力路由层
包括：
- MCP 协议接入
- Tool 注册与映射
- Skill 路由分发
- 权限校验
- 请求摘要记录

---

### 4.2.3 业务能力层
包括：
- 数据库 Skill
- 风险识别
- SQL 执行控制
- 密码加解密服务
- 数据源管理
- 审计日志服务

---

### 4.2.4 数据访问层
包括：
- PostgreSQL 系统库访问
- JDBC 目标数据库访问
- 配置文件读取
- secret 文件读取

---

# 5. 技术选型说明（Java 方案）

## 5.1 选型结论
本项目正式方案采用 Java 技术路线，原因如下：

- 更适合企业内部长期维护
- JDBC 对老数据库兼容性成熟
- 更适合权限、审计、配置管理等后台能力建设
- 更适合后续规范化扩展

---

## 5.2 技术栈建议

### 后端
- Java 17
- Spring Boot
- Spring Security
- MyBatis
- HikariCP
- JDBC

### 前端
- Vue 3
- Vite
- TypeScript
- Element Plus

### 数据存储
- PostgreSQL

### 部署方式
- Jar 包部署
- systemd 守护
- Nginx 反向代理

---

## 5.3 版本兼容建议
考虑 Oracle 11g、MySQL 5.6 等老版本数据库兼容性，建议：

- 目标数据库访问尽量采用原生 JDBC
- 不依赖数据库新特性
- 避免对目标库使用强绑定 ORM
- 驱动版本需在联调前完成专项验证

# 7. MCP 架构设计

## 7.1 设计目标
MCP 层不应设计为“仅供 SQL 执行的固定模块”，而应设计为统一能力入口，以支持未来扩展其他 Skill。

---

## 7.2 MCP 统一入口机制
MCP 层承担以下职责：

- 接收 Claude Code 调用
- 识别 Tool
- 路由到目标 Skill
- 进行权限校验
- 记录调用日志
- 返回标准结果

---

## 7.3 Skill 插件式扩展原则
首期落地：
- `database skill`

后续预留：
- `file skill`
- `log skill`
- `config skill`
- `deploy skill`

扩展方式原则上通过：
- 新增 Skill 模块
- 注册到 Skill Registry
- 配置权限和可见性
- 接入统一审计和状态监控

---

## 7.4 Database Skill 工具建议
首期数据库 Skill 可提供以下 Tool：

- `execute_sql_file`
- `execute_sql_text`
- `validate_sql`
- `list_datasources`
- `get_execution_status`

---

# 8. Web 管理端设计

## 8.1 Web 端定位
Web 管理端主要用于“管理与查看”，不作为主要 SQL 编写执行入口。

---

## 8.2 页面建议清单
建议首期包含以下页面：

1. 登录页  
2. 首页 / 系统概览页  
3. 数据源管理页  
4. 密码加解密管理页  
5. 用户与权限管理页  
6. 审计日志页  
7. MCP 调用状态页  
8. 系统配置页  

---

## 8.3 MCP 调用状态页说明
MCP 调用状态页需按 **skill/tool** 维度展示，而不是仅按 SQL 维度展示。

建议展示字段包括：

- 调用时间
- 调用人
- Skill 名称
- Tool 名称
- 请求摘要
- 数据源
- 目标环境
- 风险等级
- 执行状态
- 执行耗时
- 错误信息
- 审计编号

---

## 8.4 密码加解密页面说明
页面需支持：

- 明文密码输入后调用后端进行加密
- 展示密文结果
- 支持将密文写入数据源配置
- 管理员可执行密文解密校验

要求：
- 前端不直接实现真实加解密逻辑
- 所有解密操作均需写入审计日志
- 解密权限仅对授权管理员开放

---

# 10. 安全设计说明

## 10.1 密码存储原则
- 不保存目标数据库明文密码
- 数据库连接密码以密文形式存储
- 加解密密钥独立于业务配置存储

---

## 10.2 加解密建议
建议采用：
- AES 对称加密方案

密钥管理方式：
- 存放于独立 secret 文件
- 不写死在代码中
- 不在前端暴露真实密钥

---

## 10.3 权限控制原则
权限控制建议覆盖以下维度：

- 用户
- 角色
- Skill
- Tool
- 环境
- 数据源

---

## 10.4 审计要求
以下操作必须审计：

- MCP 调用
- SQL 执行
- 数据源配置变更
- 密码加密操作
- 密码解密操作
- 权限配置修改

---

# 11. 目标数据库兼容性设计

## 11.1 支持范围
首期重点兼容：

- Oracle 11g
- MySQL 5.6

---

## 11.2 兼容性原则
- 使用 JDBC 原生方式连接目标数据库
- 驱动版本按数据库版本单独适配
- SQL 执行逻辑避免依赖数据库新特性
- 对存储过程、多语句、结果集处理做差异化适配

---

## 11.3 兼容性关注点
### Oracle 11g
需关注：
- JDBC 驱动兼容性
- 字符集
- 日期时间类型
- 存储过程调用方式
- 游标处理

### MySQL 5.6
需关注：
- 驱动版本兼容性
- 时区设置
- 字符编码
- 多语句执行支持
- 旧版认证兼容

# 12. 部署架构说明

## 12.1 部署原则
本项目不采用 Docker 部署，采用简化、易维护的传统部署方式。

---

## 12.2 推荐部署方式

### 服务端部署
- Java 应用打包为 Jar
- 使用 systemd 守护进程运行
- 使用 Nginx 提供前端静态资源和反向代理

### 本地部署
- 通过 `java -jar` 启动服务
- 前端可打包后由后端统一托管，或静态部署

---

## 12.3 部署组成
建议部署组成如下：

- `Platform-MCP-app.jar`
- 前端静态资源
- PostgreSQL 数据库
- 应用配置文件
- secret 密钥文件
- systemd 服务配置
- Nginx 配置

# 13. 实施边界说明

## 13.1 首期纳入范围
首期建议纳入范围：

- Java 后端服务建设
- Web 管理端建设
- MCP 统一入口建设

## 13.2 首期不纳入范围
首期建议不纳入：

- 复杂工作流审批
- 大规模分布式调度
- 多 Skill 同步开发落地
- Web 在线 SQL 编辑器深度建设

---

# 14. 风险与建议

## 14.1 主要风险
1. 老数据库驱动兼容性风险  
2. SQL 多语句与存储过程差异处理风险  
3. 密码解密权限控制风险  
4. MCP 调用链路审计完整性风险  
5. 后续 Skill 扩展时接口规范不统一风险  

---

## 14.2 对应建议
1. 提前完成 Oracle 11g、MySQL 5.6 驱动验证  
2. 第一阶段明确数据库支持矩阵和能力边界  
3. 严格限制解密权限并记录审计  
4. MCP 调用、执行、返回全链路统一记录  
5. 在首期即固化 Skill 接口标准和注册机制  

---

# 15. 方案结论

## 15.1 结论摘要
Platform_MCP 项目建议采用以下正式技术方案：

- 采用 **Java 单体模块化架构**
- 采用 **MCP 统一入口 + Skill 插件式扩展思路**
- 首期落地 **database skill**
- Web 端作为 **管理与审计控制台**
- 系统库采用 **PostgreSQL**
- 目标数据库采用 **JDBC** 连接
- 优先兼容 **Oracle 11g** 与 **MySQL 5.6**
- 采用 **Jar + systemd + Nginx** 部署方式
- 保留后续扩展其他 Skill 的能力
