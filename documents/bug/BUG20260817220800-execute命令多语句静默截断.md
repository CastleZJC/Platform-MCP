# BUG：execute_command 多语句静默截断 — `;`/`&&`/`||` 后命令全部丢弃

**严重级别**：High（静默部分执行，调用方以为整串命令已跑完）
**发现日期**：2026-08-17（V1.1.4 发布当日复核发现）
**发现环境**：PROD（linux-app-dev 目标服务器实测，MCP 服务器 192.0.2.216）
**引入版本**：V1.1.0（2026-08-16 审计源系统会话标识专项引入 `echo $$; exec` 包装）

---

## 1. 现象

`execute_command` 传入多语句命令（含 `;`、`&&`、`||`），只有**第一条**命令执行，其余静默丢弃且返回 exit 0：

```
命令: echo A; echo B; pwd; id          实际 stdout: "A\n"（仅此）
命令: rm a.txt && ls | head -5         实际: 只删 a.txt，ls 不执行，stdout 空
```

单命令不受影响 → V1.1.0 起两天内所有单命令冒烟/业务全正常，链式命令的"验证后半段"从未真正跑过。

## 2. 根因

`skills/server/executor.py` 为捕获审计用 SSH PID，把命令包装为：

```python
wrapped = f"echo $$; exec {command}"
```

POSIX `exec` 是**用命令替换当前 shell 进程**：`exec echo A; echo B; pwd` 中 shell 先执行 `exec echo A` → 进程被 `echo A` 替换 → 打印 A 后进程退出 → **分号后的 `echo B; pwd` 永远不会执行**，且 exit status 来自 `echo A`（0）。

## 3. 修复（V1.1.5）

```python
wrapped = f"echo $$; exec bash -c {shlex.quote(command)}"
```

- 完整命令串作为 `bash -c` 的单一参数（`shlex.quote` 安全转义，含单引号/分号/管道均原样承载）
- `exec bash -c` 后 PID 不变，`echo $$` 捕获的 source_session PID 语义保持
- 回归用例：`tests/unit/test_server_executor.py::test_多语句命令_完整包装不截断`（断言包装形态 + 不裸拼 + PID 解析）

## 4. 验证（2026-08-17 生产实测，修复部署后）

| 用例 | 结果 |
|---|---|
| `echo A; echo B; pwd; id` | ✓ 全量输出（A/B/家目录/uid），修复前仅 "A" |
| `touch …; ls -l …; rm -f …; ls …; echo CHAIN_DONE` | ✓ 五段按序全执行（建→列→删→验不存在→DONE） |
| 段一全量 | pytest 801 passed / mypy 0 errors(76 files) / vue-tsc 0 / vitest 117 |

部署：executor.py 单文件 LF 上传（带日期备份后缀）+ 重启 MCP + 401 健康。段四：`__MCP_VERIFY_` 标记行清理。

## 5. 影响面回溯（V1.1.0 → V1.1.4 期间）

- 所有**链式** execute_command 调用均只执行了第一段（含 V1.1.4 冒烟中 `rm … && ls` 类验证命令的验证段）
- 单命令调用（历史业务主体）零影响
- 其余受管目标服务器同码同缺陷，随本修复一并生效
