MCP 接入指南

如何将 Platform-MCP 接入 Claude Code 等 MCP 客户端

推荐 远程服务器部署

streamable-http 模式，适用于已部署到 Linux 服务器的生产环境。

  1. 获取部署服务器的实际 IP 或域名（如 192.168.1.100 / mcp.example.com），替换下方配置中的 <your-server-ip>
  2. 在 Web 管理端登录 → “个人设置” 查看你的 API Key
  3. 复制 API Key，替换下方配置中的 <your-api-key>
  4. 将配置写入 Claude Code 配置文件：~/.claude.json
  5. 重启 Claude Code 即可自动连接

配置写入 ~/.claude.json：

{
  "mcpServers": {
    "Platform-MCP": {
      "url": "http://<your-server-ip>:9000/mcp/",
      "transport": "http",
      "headers": {
        "PLATFORM_MCP_API_KEY": "<your-api-key>"
      }
    }
  }
}
替换提示：
  • <your-server-ip>
  • <your-api-key>

仅限本机 本地开发调试

stdio 模式，Claude Code 与本机 MCP Server 通过子进程通信。不对外开放。

  1. 确认本机已安装 Python 3.11.9+ 及所有依赖
  2. 在本机运行 python -m platform_mcp.mcp_server 确认可启动
  3. 将配置写入 Claude Code 配置文件：~/.claude.json

配置示例（仅本机开发）：

{
  "mcpServers": {
    "Platform-MCP": {
      "command": "python",
      "args": ["-m", "platform_mcp.mcp_server"],
      "env": {
        "PLATFORM_MCP_ENV": "dev",
        "PLATFORM_MCP_API_KEY": "<your-api-key>"
      }
    }
  }
}

使用建议

通过 Claude Code 调用 Platform-MCP 执行 SQL 或 Shell/SFTP 操作时，可以用以下方式指定数据源/服务器，Claude 会按场景自动解析并选择对应 skill（database / server）。

场景示例指令Claude 行为
模糊匹配数据源（SQL） 用 app-sample-1 执行 documents/samples/x.sql Claude 查询 list_datasources，按 app-sample-1 子串匹配 datasource_code / name / host；唯一命中直接执行，多匹配时弹出候选让用户选择
显式选择数据源（SQL） 执行 documents/samples/x.sql Claude 列出当前角色可访问的数据源（admin 全部，developer 自动排除 PROD），让用户选择后执行
完整指定数据源（SQL） 用 ora-app-dev 执行 x.sql 直接调用 execute_sql_file，无中间交互
模糊匹配服务器（Shell） 在 linux-app-dev 上执行 uname -a Claude 查询 list_servers，按 linux-app-dev 子串匹配 server_code / name / host；唯一命中直接执行 execute_command，多匹配时弹候选
上传/下载文件（SFTP） 把 D:\pkg\x.tar.gz 传到 linux-app-dev 的 /tmp/ Claude 自动编排工作站→MCP 中转→目标服务器的完整传输链路并自动清理中转文件，用户只需描述来源与去向
Claude 自动判断 SQL vs Shell app-sample-1 上查 Oracle 的 dual 表 / linux-app-dev 上看磁盘空间 Claude 依据意图自动选 execute_sql_text 或 execute_command；模糊场景（如『linux-app-dev 上检查一下』）Claude 会反问用户：『是查 Oracle 数据库还是看服务器磁盘？』，确认后再调用对应 skill
  • 数据源/服务器关键字优先用编码片段（如 app-sample-1、app-sample-2），匹配精度高于主机名
  • PROD 环境仅 admin 可执行，developer 角色会被自动过滤
  • HIGH / CRITICAL 风险 SQL 或 Shell 命令会先返回 confirm_token，Claude 会自动完成二次确认
  • Shell：rm -rf 根目录、mkfs、dd 写块设备、fork bomb、shutdown 等直接判 CRITICAL；sudo / systemctl stop 等判 HIGH
  • SFTP：直接用自然语言描述上传/下载需求（如『把 D:\pkg\x.zip 传到 linux-app-dev 的 /tmp/』），Claude 自动完成中转搬运与清理；文件上限 500MB；写入 /etc /boot 等系统目录强制 CRITICAL，需二次确认
  • Claude 自动意图识别：依据用户语义选择 database/server skill；当指令模糊（如『检查一下 linux-app-dev』）时反问用户，避免误用 skill
  • 意图识别补充验证：用户在指令断言中包含 SQL 关键字（SELECT/INSERT/UPDATE/DELETE/表名/视图）→ database；包含 shell 关键字（执行/传输/上传/下载/cron/服务/进程/磁盘）→ server；同时命中或都不命中 → 反问

常见问题

MCP Server 启动失败 — module not found
确认 Platform-MCP 已安装: pip install -e . 检查 PLATFORM_MCP_ENV 环境变量是否设置
Oracle 连接错误 DPY-3010
Oracle 11g 需要 thick 模式。确认 instant_client_dir 配置指向正确的 Oracle Instant Client 目录
Tools 在 Claude Code 中不可见
检查 Claude Code 的 MCP 配置 JSON 格式是否正确，command 路径是否为 python 的完整路径
数据库连接测试超时
检查网络连通性和防火墙规则，确认目标数据库允许从本机 IP 连接
权限不足错误
PROD 环境数据源仅 admin 角色可调用。确认当前角色和数据源环境标识正确
